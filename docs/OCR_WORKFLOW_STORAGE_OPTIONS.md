# OCR Workflow Storage Options

## Overview

This document outlines the available storage options for the OCR-processed Epstein document files generated by the GitHub Actions workflow. Each option has different trade-offs in terms of cost, accessibility, retention, and complexity.

## Storage Options Comparison

### Option 1: GitHub Actions Artifacts ⭐ (Recommended for CI/CD)

**Description**: Store processed files as GitHub Actions workflow artifacts.

**Pros**:
- ✅ No additional setup required
- ✅ Free for public repositories
- ✅ Integrated with GitHub workflow
- ✅ Easy to download from Actions UI
- ✅ No external dependencies
- ✅ Automatic cleanup after retention period

**Cons**:
- ❌ Maximum 90-day retention (configurable)
- ❌ Not ideal for long-term public distribution
- ❌ Requires GitHub account to download
- ❌ Limited to 2GB per artifact (can split into multiple)

**Cost**: Free for public repositories

**Best For**: 
- CI/CD verification
- Temporary processing results
- Development and testing
- Short-term access

**Implementation**: Already supported natively in GitHub Actions

```yaml
- name: Upload OCR Results
  uses: actions/upload-artifact@v4
  with:
    name: ocr-processed-documents
    path: epstein_artifacts/
    retention-days: 90
```

---

### Option 2: Cloudflare R2 Storage ⭐⭐ (Recommended for Public Distribution)

**Description**: Store files in Cloudflare R2 object storage with public access.

**Pros**:
- ✅ Long-term storage
- ✅ Public HTTP access (no authentication needed)
- ✅ No egress fees (unlike AWS S3)
- ✅ Global CDN distribution
- ✅ Custom domain support
- ✅ S3-compatible API
- ✅ Cost-effective for large files

**Cons**:
- ❌ Requires Cloudflare account setup
- ❌ Additional configuration needed
- ❌ Storage costs (though minimal)
- ❌ Need to manage bucket lifecycle

**Cost**: 
- Storage: $0.015/GB/month
- No egress fees (unlimited downloads)
- Example: 100GB = $1.50/month

**Best For**:
- Public distribution of processed documents
- Long-term archival
- High-volume downloads
- Making datasets publicly accessible

**Setup Requirements**:
1. Cloudflare account with R2 enabled
2. R2 bucket created
3. API tokens configured in GitHub secrets
4. Public access policy enabled

**Implementation**: Requires Wrangler CLI or rclone

```yaml
- name: Upload to Cloudflare R2
  env:
    CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
    CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_R2_TOKEN }}
  run: |
    # Install Wrangler CLI
    npm install -g wrangler
    
    # Upload to R2 bucket
    wrangler r2 object put epstein-documents/ocr-$(date +%Y%m%d).tar.gz \
      --file ./ocr-results.tar.gz
```

### Option 3: GitHub Repository Storage ⚠️ (Not Recommended for Large Files)

**Description**: Commit processed files directly to the repository.

**Pros**:
- ✅ Version controlled
- ✅ Permanently accessible
- ✅ Simple git workflow
- ✅ Included in repository clones

**Cons**:
- ❌ GitHub has 100MB file size limit
- ❌ Increases repository size
- ❌ Slow clones for large repos
- ❌ Not suitable for binary files
- ❌ Git LFS required for large files
- ❌ Affects repository performance

**Cost**: Free for public repos (soft limit: 100GB repository size)

**Best For**:
- Small result files (manifests, summaries)
- Metadata and indexes
- Text-based outputs only

**Implementation**:

```yaml
- name: Commit Results to Repository
  run: |
    git config user.name "github-actions[bot]"
    git config user.email "github-actions[bot]@users.noreply.github.com"
    git add results/manifest.jsonl results/summary.json
    git commit -m "Add OCR processing results"
    git push
```

### Option 4: GitHub Releases ⭐ (Good for Versioned Datasets)

**Description**: Attach processed files to GitHub releases.

**Pros**:
- ✅ Public HTTP download links
- ✅ Versioned datasets
- ✅ Integrated with GitHub
- ✅ No authentication required for public repos
- ✅ 2GB per file limit
- ✅ Permanent storage

**Cons**:
- ❌ Requires release/tag creation
- ❌ Not automatic (needs workflow step)
- ❌ 2GB per file limit

**Cost**: Free for public repositories

**Best For**:
- Versioned dataset releases
- Periodic snapshots
- Official document releases
- Public downloads

**Implementation**:

```yaml
- name: Create Release with OCR Results
  uses: softprops/action-gh-release@v1
  with:
    tag_name: ocr-${{ github.run_number }}
    name: OCR Processing Run ${{ github.run_number }}
    files: |
      ocr-results.tar.gz
      manifest.jsonl
```

### Option 5: External Cloud Storage (AWS S3, Azure Blob, GCS)

**Description**: Use traditional cloud storage providers.

**Pros**:
- ✅ Enterprise-grade reliability
- ✅ Advanced features (lifecycle, versioning)
- ✅ Well-documented APIs
- ✅ Integration with other services

**Cons**:
- ❌ Egress fees (AWS S3: $0.09/GB)
- ❌ More expensive than R2
- ❌ Complex pricing
- ❌ Additional account setup

**Cost**: Varies by provider (typically more expensive than R2)

**Best For**: Organizations already using these platforms

## Recommended Strategy

### For This Project: Hybrid Approach

1. **GitHub Actions Artifacts** (Short-term, 90 days)
   - Store all OCR results as workflow artifacts
   - Useful for verification and testing
   - Free and automatic

2. **Cloudflare R2** (Long-term, public)
   - Archive important processed document sets
   - Make publicly accessible via HTTP
   - Cost-effective for large datasets
   - Setup as optional/manual step

3. **GitHub Repository** (Metadata only)
   - Commit manifests, indexes, and summaries
   - Track which documents have been processed
   - Keep file sizes under 1MB

4. **GitHub Releases** (Versioned snapshots)
   - Create periodic releases with curated datasets
   - Tag significant document collection milestones
   - Easy public download

## Implementation in Workflow

The workflow will support multiple outputs:

```yaml
outputs:
  artifacts:
    enabled: true          # Always enabled (free)
    retention-days: 90
  
  cloudflare-r2:
    enabled: false         # Optional, requires setup
    bucket: "epstein-documents"
    public: true
  
  repository:
    enabled: true          # Metadata only
    paths:
      - "results/manifests/*.jsonl"
      - "results/indexes/*.json"
  
  release:
    enabled: false         # Manual/periodic
    create-on: tag
```

## Cloudflare R2 Setup Guide

### Prerequisites
1. Cloudflare account (free tier available)
2. R2 subscription enabled (pay-as-you-go)

### Setup Steps

1. **Enable R2 in Cloudflare Dashboard**
   - Go to https://dash.cloudflare.com/
   - Navigate to R2 section
   - Click "Create bucket"

2. **Create R2 Bucket**
   - Name: `epstein-documents`
   - Region: Automatic (closest to users)
   - Public access: Enable

3. **Generate API Token**
   - Go to R2 > Manage R2 API Tokens
   - Create API Token with:
     - Permission: Object Read & Write
     - Bucket: epstein-documents
   - Save Account ID and API Token

4. **Configure GitHub Secrets**
   - Go to repository Settings > Secrets and variables > Actions
   - Add secrets:
     - `CLOUDFLARE_ACCOUNT_ID`: Your account ID
     - `CLOUDFLARE_R2_TOKEN`: Your API token
     - `CLOUDFLARE_R2_BUCKET`: `epstein-documents`

5. **Enable Public Access**
   - In R2 bucket settings, enable public access
   - Configure custom domain (optional)
   - Example URL: `https://pub-xxxx.r2.dev/epstein-documents/`

6. **Configure CORS (if needed)**
   ```json
   {
     "AllowedOrigins": ["*"],
     "AllowedMethods": ["GET", "HEAD"],
     "AllowedHeaders": ["*"]
   }
   ```

### Cost Estimation

**Example Processing Run**:
- Input: 10,000 PDFs (50GB)
- Output: OCR PDFs + text files (60GB)
- Storage for 1 year: 60GB × $0.015/GB × 12 = $10.80/year
- Downloads: Unlimited (no egress fees)

**Comparison for 1TB egress**:
- AWS S3: $10.80 storage + $92.16 egress (1TB × $0.09/GB) = $102.96/year
- Cloudflare R2: $10.80/year (no egress fees)
- **Savings: $92.16/year** with R2

**Comparison for 10TB egress**:
- AWS S3: $10.80 storage + $921.60 egress (10TB × $0.09/GB) = $932.40/year  
- Cloudflare R2: $10.80/year (no egress fees)
- **Savings: $921.60/year** with R2

*Pricing verified as of January 2025. Cloud pricing may change - check current AWS S3 and Cloudflare R2 pricing pages for latest rates.*

## Security Considerations

### Public Storage Best Practices

1. **No Sensitive Data**
   - Only public documents (DOJ, FBI releases)
   - No personal information
   - No classified materials

2. **Access Logging**
   - Enable R2 access logs
   - Monitor download patterns
   - Track bandwidth usage

3. **Content Policy**
   - Add disclaimer about document sources
   - Include usage guidelines
   - Link to original sources

4. **Backup Strategy**
   - Keep local copies
   - Use multiple storage providers
   - Regular integrity checks
